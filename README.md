# PP · น้องโจอา เลขาส่วนตัว

### รุ่นเลขาส่วนตัว · 9 ตุลาคม 2026

นัดหมายที่ **ยืนยันบันทึก** กับเลขาบนเว็บหรือ LINE จะแสดงใน **ความทรงจำ → ปฏิทิน** และรายการทั้งหมดด้วย รวมเฉพาะนัดส่วนตัวเจ้าของและนัดของกลุ่มที่เปิดใช้และเจ้าของมีสิทธิ์ คลิกรายการเพื่อแก้ชื่อ วันที่ ข้อความ ทำซ้ำทุกปี เตือนก่อนหนึ่งวัน หรือลบนัดได้ เป็นรายการเดียวกับเลขาและใช้คิวแจ้งเตือนเดิม ไม่สร้างสำเนาหรือส่งซ้ำ หากเปิดปฏิทินค้างไว้ระหว่างคุยใน LINE ให้กด **อัปเดตปฏิทิน** ประวัติแจ้งเตือนของเลขารวมอยู่ด้านล่างด้วย

เปิด `/admin/chat` เพื่อคุยกับเลขา หรือคุยกับ LINE น้องโจอาได้ตามเดิม ในกลุ่มต้องเรียก `@น้องโจอา` / `@pp` และกลุ่มต้องเปิดใช้งาน เพื่อนที่ถูกพักยังคงถูกปฏิเสธตามสิทธิ์เดิม

- **จำ**: “จำว่า ฉันชอบกาแฟไม่หวาน” เลขาสรุปให้ตรวจ พิมพ์ **ยืนยัน** หรือกด **ยืนยันบันทึก** บนเว็บจึงบันทึก **ยกเลิก** เอารายการรอยืนยันออก รายการรอยืนยันมีอายุ 15 นาที ไม่เขียนทับความจำเดิม
- **ถาม**: ถามความทรงจำเดิมและสมุดจำใหม่ได้ คำตอบจากความจำยังตรวจสิทธิ์ ข้อมูลหมดอายุ ข้อขัดกัน และ revision ตามเดิม ไม่มีการย้ายหรือลบความทรงจำเดิม
- **เตือน / นัดหมาย**: “เตือนฉันพรุ่งนี้เรื่องจ่ายค่าไฟ” หรือ “นัดหมาย 15 ตุลาคม 2026 เวลา 14:00 ไปพบเพื่อน” ตรวจวัน/ผู้รับก่อนยืนยัน คำว่า **มีนัดอะไรบ้าง** แสดงรายการถัดไปจากทั้งสมุดเลขาและปฏิทินเดิมที่มีสิทธิ์
- **คุยทั่วไป**: คุย ขอคำอธิบาย ช่วยร่างข้อความหรือคิดไอเดียได้ ใช้ Gemini และโควตาร่วมเดิม ไม่มีการท่องเว็บหรือข้อมูลสด ถ้า AI ไม่พร้อมยังถามความจำตรงคำถามและดูนัดได้

สมุดจำใหม่ของ DM แยกตาม LINE user ID; สมุดในกลุ่มใช้ร่วมกันเฉพาะกลุ่มนั้น ไม่ถูกนำไปตอบ DM หรือกลุ่มอื่น เว็บเจ้าของเลือก “ของฉัน” หรือกลุ่มที่เปิดใช้งานได้ รายการส่วนตัวของเพื่อนจะไม่ปรากฏในเว็บเจ้าของ ประวัติที่ส่งให้เลขาอ่านมีเฉพาะบทสนทนาที่เรียกเลขาใน thread ของผู้ส่ง เก็บ 30 วัน ไม่เก็บบทสนทนากลุ่มทั่วไปเพื่อเรียนรู้

การแจ้งเตือนใช้ Vercel Hobby เวลาเดิม **08:00–09:00 น. (เวลาไทย)** วันนัดและก่อนหนึ่งวันเมื่อเลือก ไม่ใช่การแจ้งเตือนตรงนาที เวลาเช่น 14:00 เป็นรายละเอียดนัดหมาย ไม่ส่งคำเชิญหรือทำปฏิทินภายนอก ส่งเฉพาะ DM ของผู้ขอหรือกลุ่มปัจจุบัน ตรวจสิทธิ์และโควตา LINE ซ้ำก่อนส่ง พร้อม retry key/payload เดิมเพื่อกันส่งซ้ำ

ใช้ migration ใหม่ `20261009065258_personal_secretary.sql` เพียงชุดเดียว เพิ่มตาราง `pp.assistant_*` และฟังก์ชัน server-only/RLS ไม่แตะความทรงจำ ปฏิทินเดิม `public` schema หรือทรัพยากรอื่น ไม่รัน migrations เก่าซ้ำ สมุดละไม่เกิน 200 ความจำ / 100 นัดหมาย

**Content Planner นำออกแล้ว** เมนู/หน้าจอ/cron หยุดทำงาน ลิงก์เก่าไปหน้าเลขา Server Actions เก่าปฏิเสธหลังตรวจแอดมิน `/api/content-reminders` ตอบ 410 และไม่ส่ง LINE ข้อมูล Content Planner เดิมยังเก็บไว้เพื่อไม่ลบข้อมูลโดยไม่จำเป็น

รายละเอียดฟังก์ชันความทรงจำเดิมด้านล่างยังใช้งานร่วมกับเลขาได้ เว้นแต่ระบุว่านำออกแล้ว

### คำตอบหลายชุดในก้อนความจำ · 5 ตุลาคม 2026

เปิดก้อนเดิมหรือเพิ่มความจำ กรอก **คำตอบที่ 1** แล้วกด **เพิ่มคำตอบ** ได้รวม 1–20 ชุด ชุดละไม่เกิน 2,000 ตัวอักษร แต่ละชุดขึ้นบรรทัดใหม่ได้ ปุ่มลบเอาคำตอบเพิ่มเติมออก คำตอบเดิมคงเป็นชุดที่ 1 บอทสุ่มส่งหนึ่งชุดเมื่อพบก้อนนั้น ทั้ง exact/semantic และกลุ่ม/แชตส่วนตัว การสุ่มอาจซ้ำ ไม่มีการเรียก AI เพิ่มเพื่อสุ่มหรือแต่งคำตอบ แต่การตรวจความจำและจับความหมายยังใช้ AI ตามเดิม ควรกรอกแต่ละชุดให้ตอบคำถามเดียวกันได้

เก็บคำตอบเพิ่มเติมใน pp.memories.answer_variants; การค้นหา การตรวจซ้ำ การรวมข้อมูล และ Gemini จับความหมายอ่านคำตอบเพิ่มเติมด้วย ตรวจสิทธิ์ อายุข้อมูล และ revision ก่อนสุ่ม; แท็กและไฟล์แนบใช้การตั้งค่าของก้อนเดิม Migration 20261005112537_pp_memory_answer_variants.sql ใช้ใน Production แล้ว และเก็บ revision ของประเด็นขัดกันเดิมไว้ ไม่แก้เนื้อหาความจำเดิม

### ผู้ช่วยจัดการความจำ 3 อย่าง · 1 ตุลาคม 2026

- เพิ่มความจำโดยกรอก **ชื่อความจำ + ข้อมูลที่อยากให้จำ** คำถามตัวอย่างเป็นตัวเลือก Gemini อ่านชื่อ เนื้อหา และตัวอย่างของทุกก้อนที่มีสิทธิ์ใช้ตอบ ไม่ต้องเพิ่มคำถามทุกสำนวน เมื่อแก้ข้อมูลจะใช้ข้อมูลล่าสุดในการถามครั้งถัดไป
- ก่อนบันทึก ระบบเปรียบเทียบกับก้อนเดิม หากซ้ำหรือเกี่ยวข้องจะแสดง **แก้ก้อนเดิม / รวมข้อมูล / เก็บแยกเป็นก้อนใหม่** การรวมเปิดข้อความให้เจ้าของตรวจและแก้ก่อน ไม่แต่งข้อเท็จจริงเพิ่ม เมื่อยืนยันจะบันทึกและลบก้อนต้นทางในธุรกรรมเดียว
- ใต้รายการความจำมี **ความจำที่ต้องตรวจ** และปุ่ม **ตรวจความจำทั้งหมด** สำหรับความจำเดิม ระบบเก็บคู่ข้อมูลขัดกันและระงับการใช้คู่นั้นตอบจนตรวจแก้ หากเลือกเก็บแยกแต่ยังตอบคำถามเดียวกันคนละอย่าง บอทยังขอให้เจ้าของตรวจ

การตรวจตอนบันทึกและปุ่มตรวจทั้งหมดใช้ Gemini และโควตาร่วมกับการตอบคำถาม ถ้า AI ไม่พร้อม ข้อมูลไม่ถูกบันทึกทันที ต้องเลือกบันทึกโดยยังไม่ได้ตรวจด้วย AI เอง ความจำเดิมไม่ถูกแก้หรือรวมอัตโนมัติ นำระบบเรียนรู้บทสนทนากลุ่มออกแล้ว

ใช้ migrations `20261001081525_pp_memory_assistant.sql` และ `20261001084039_pp_memory_issue_layout.sql` ทั้งสองใช้ใน Production แล้ว ตาราง `pp.memory_issues` เป็น server-only และการเปลี่ยนสี/เรียงการ์ดไม่ล้างข้อขัดกัน ระบบตรวจ snapshot ซ้ำภายใต้ lock ก่อนบันทึกเพื่อไม่ทับข้อมูลที่เปลี่ยนระหว่างรอ AI

ขอบเขต: AI อ่านข้อความ ไม่อ่านเนื้อหาภายในรูปหรือไฟล์แนบ; การจับคู่และตรวจซ้ำอาจผิดพลาด ปุ่มตรวจทั้งหมดรายงานสูงสุด 40 คู่ต่อรอบ ชุดข้อมูลเกิน 128,000 UTF-8 bytes จะไม่ถูกตัดบางก้อนอย่างเงียบ ๆ แต่หยุด AI และแจ้งข้อจำกัด ไม่มี vector index หรือการฝึกโมเดลใหม่ คิวตรวจนี้ใช้กับความจำที่เจ้าของเพิ่มเอง ไม่มีการสร้างข้อเสนอจากบทสนทนากลุ่มแล้ว

### AI จับความหมายทั้งกลุ่มและแชตส่วนตัว · 1 ตุลาคม 2026

กลุ่มที่เปิดใช้งานเรียกด้วย `@pp` / `@น้องโจอา` หรือ mention จริง แชตส่วนตัวกับบอทใช้ได้ทั้งเจ้าของและเพื่อน พิมพ์คำถามได้เลย เมื่อไม่ตรงตัวอย่างที่บันทึกไว้จึงใช้ Gemini จับความหมาย เช่น `น้ำท่วมป่ะ` / `น้ำท่วมไหม` จับคู่กับ `มีน้ำท่วมไหม` แล้วส่งคำตอบที่เจ้าของบันทึก ไม่สร้างคำตอบใหม่หรือเรียนรู้ทุกคำถามอัตโนมัติ ไม่มีการเก็บข้อความเพื่อเรียนรู้จากกลุ่มแล้ว

ทุกแชตใช้เพดาน AI ร่วมกัน 6 ครั้ง/นาทีและ 1,000 ครั้ง/เดือน คำถามที่ตรงตัวอย่างไม่เรียก AI ผู้ส่ง DM ที่ถูกพักในรายชื่อเพื่อนของกลุ่มใดจะไม่ได้รับคำตอบ ยกเว้นบัญชีเจ้าของ ข้อมูล shareable ใช้ตอบผู้ทัก DM ได้แม้ยังไม่เคยอยู่ในกลุ่ม ส่วนความจำที่เรียนรู้จากกลุ่มไม่ถูกนำออกมาตอบ DM ข้อมูล private เก่าคงสิทธิ์เจ้าของและไม่ส่งเข้า AI

ใช้ migrations `20261001072625_pp_owner_semantic_matching.sql` และ `20261001073157_pp_direct_semantic_chat.sql` ก่อน deploy ทั้งสองใช้บน Production แล้ว ทดสอบ Gemini จริงผ่าน 8/8 ข้อ รวมสำนวนคำถามน้ำท่วมและการแยกคำถามพยากรณ์คนละสถานที่ รายละเอียดส่งมอบล่าสุดใน DEPLOYMENT/HANDOFF แทนข้อจำกัดแชตส่วนตัวในประวัติรุ่นก่อน

### ความจำพร้อมแบ่งปัน · 1 ตุลาคม 2026

ยกเลิกตัวเลือก Private/Shareable ในฟอร์มความจำและคลังไฟล์ รวมป้ายและตัวนับส่วนตัว ความจำและไฟล์ใหม่พร้อมให้บอทใช้ตอบในกลุ่มที่อนุมัติ โดยเพิ่มเป็น shareable เสมอ ไม่บังคับคำที่กรองเจอให้เปลี่ยนเป็น Private และไม่ตัดคำตอบที่เจ้าของยืนยันด้วยตัวกรองคำ เช่น “รหัสสินค้า” Gemini ยังเลือกได้เฉพาะความจำที่อนุมัติแล้วและ SQL ตรวจสิทธิ์ซ้ำ ไม่แต่งคำตอบเอง ระบบเรียนรู้จากบทสนทนายังคัดกรองและรอเจ้าของอนุมัติตามเดิม

Migration `20261001070842_pp_shareable_defaults.sql` เปลี่ยนเฉพาะค่าเริ่มต้น ไม่เผยแพร่ข้อมูลเดิมซ้ำ ก่อนอัปเดตมีความจำ 10 รายการและไฟล์ 1 รายการเป็น shareable ทั้งหมด ระบบหลังบ้านยังป้องกัน legacy private หากมีการนำเข้าข้อมูลเก่า ที่เก็บไฟล์ยังไม่เป็น public และหน้าแอดมินยังต้องเข้าสู่ระบบ

### ข้อความเมื่อไม่รู้คำตอบ

ที่ **สิทธิ์/เพื่อน/ประวัติ → ข้อความเมื่อไม่รู้คำตอบ** กด **เพิ่มข้อความ** เพื่อกรอกเองได้ 1–20 ชุด แต่ละชุดเขียนหลายบรรทัดได้ สูงสุด 2,000 ตัวอักษร กด **ลบ** เอาชุดที่ไม่ใช้ออก แล้ว **บันทึกข้อความ** บอทสุ่มใช้ครั้งละหนึ่งชุดกับ unknown ทั้งในกลุ่มและแชตส่วนตัวกับบอท การสุ่มอาจซ้ำกันได้ โดยอ่านรายการล่าสุดทุกคำถาม เริ่มต้นมีเพียง **ยังไม่มีข้อมูลเรื่องนี้** ไม่เติมตัวเลือกแทนเจ้าของ ไม่เปลี่ยนคำตอบจากความจำ การปฏิเสธจากการตรวจสิทธิ์ หรือการแท็กเจ้าของ เก็บใน `pp.owner.unknown_replies` ผ่าน Server Action เฉพาะแอดมิน

### ระบบเรียนรู้จากกลุ่ม — นำออกแล้ว 5 ตุลาคม 2026

ไม่มีเมนูเรียนรู้จากกลุ่ม ไม่เก็บข้อความสำหรับเรียนรู้ และไม่เรียก Gemini เพื่อสรุปกลุ่มจาก webhook หรืองานประจำวัน ลิงก์ /admin/learning จะกลับไปหน้าความทรงจำ คำสั่งจากหน้าเก่าจะไม่เปิดใช้งานหรือแก้ข้อมูลอีก

ปิด learning_enabled ของทุกกลุ่มเดิมแล้ว ความจำที่เจ้าของเพิ่มเอง การจับความหมาย การเก็บรายชื่อเพื่อน ยังคงทำงาน ตาราง/ฟังก์ชันฐานข้อมูลเดิมคงไว้เพื่อความเข้ากันได้และการล้างข้อมูลตามอายุเดิม ไม่ลบความจำหรือข้อมูลกลุ่ม

### สีและลำดับก้อนความจำ

ก้อนความจำสูง 116px จอคอม 10 คอลัมน์ หน้าละ 20 รายการ ความจำใหม่เพิ่มต่อท้ายลำดับที่จัดไว้ ช่องค้นหาอยู่ข้างปุ่มเพิ่มความจำ กดค้างแล้วลากทั้งก้อนบนหน้าปกติเพื่อเรียงและบันทึกอัตโนมัติ คลิกครั้งเดียวเพื่อแก้ไข หรือใช้ Alt+ลูกศรซ้าย/ขวาเพื่อเลื่อนตำแหน่ง กด **จัดเรียง/สี** เพื่อปรับแบบร่างหรือใช้ปุ่มเลื่อน เลือกเขียว/เหลือง/แดง/ฟ้า กดสีเดิมเพื่อล้างสี แล้ว **บันทึกสีและลำดับ** การจัดเรียงผลค้นหาจะรักษาตำแหน่งของความจำอื่นที่ไม่แสดง ข้อมูลจัดเก็บใน pp.memories ผ่าน RPC ที่อนุญาตเฉพาะเซิร์ฟเวอร์หลังตรวจแอดมิน สีไม่มีผลต่อการเลือกคำตอบ
### เลือกไฟล์ตามโฟลเดอร์และชื่อเพื่อน

ฟอร์มความจำและปฏิทินให้เลือกโฟลเดอร์งานก่อนดูรูป/ไฟล์ รวมหมวดไม่จัดโฟลเดอร์ เลือกข้ามโฟลเดอร์ได้รวมสูงสุด 10 ไฟล์ มีรายการที่เลือกแล้วให้เอาออก และเก็บไฟล์แนบเดิมไว้เมื่อแก้ไข รายการส่งกลุ่มเลือกได้เฉพาะไฟล์ Shareable

เมื่อเลือกกลุ่ม ช่องแท็กเพื่อนโหลดชื่อ LINE ที่ยังขาดผ่าน Server Action เฉพาะแอดมิน ตรวจกลุ่มเปิดใช้งานและเพื่อนที่ไม่ถูกพัก เติมชื่อไม่เกิน 20 คนต่อครั้ง ทำพร้อมกันสูงสุด 4 คน ไม่เขียนทับชื่อที่เจ้าของตั้งหรือแก้ระหว่างโหลด และไม่ทำให้หน้าแรกต้องรอ LINE API เจ้าของมีป้าย (ฉัน); คนที่ยังไม่รู้ชื่อมีทางไปแก้ชื่อใน สิทธิ์/เพื่อน/ประวัติ ในกลุ่มที่เปิดใช้งาน ระบบรับชื่อ/รหัสเพื่อนจากข้อความ สติกเกอร์ และสมาชิกเข้าใหม่โดยไม่ต้องเรียกบอท ไม่เก็บข้อความหรือเรียก AI จากการเก็บรายชื่อ หน้า สิทธิ์/เพื่อน/ประวัติ มีปุ่มอัปเดตรายชื่อเพื่ออ่านรายชื่อทั้งหมดผ่าน LINE เมื่อประเภทบัญชีรองรับ หาก LINE ตอบ 403 จะแจ้งให้สมาชิกส่งข้อความหนึ่งครั้งแล้วอัปเดตอีกครั้ง พร้อมโหลดชื่อที่ยังขาด ไม่ลบรายชื่อเก่าหรือเปลี่ยนสถานะพักการตอบ

เอาคำอธิบายยาวใต้ฟอร์มปฏิทินออกตามคำขอ เวลาและเงื่อนไขส่งแจ้งเตือนคงเดิม

## ใช้เป็นแอปบนคอม

- เปิด https://pp-theta-beryl.vercel.app/install ใน Chrome หรือ Edge แล้วกด **ติดตั้งบนคอม** หรือใช้ไอคอนติดตั้งบนแถบที่อยู่ มีปุ่มติดตั้งในเมนูด้านล่างของหน้าแอดมินด้วย
- แอปชื่อ **น้องโจอา** เปิด `/admin` ในหน้าต่างแยกจากเบราว์เซอร์ ค้นหาใน Start และปักหมุด Taskbar ได้ ใช้บัญชีและฐานข้อมูลเดิม
- ต้องเชื่อมต่ออินเทอร์เน็ต เว็บและแอปใช้ deployment เดียวกัน ไม่มี service worker/offline cache จึงไม่เก็บสำเนาความจำเพื่อใช้งานออฟไลน์ และไม่มี native bridge หรือสิทธิ์เข้าถึงระบบเพิ่ม
- Manifest `/manifest.webmanifest` เป็น public static metadata; หน้าแอดมินและไฟล์ส่วนตัวยังต้องตรวจบัญชีเจ้าของตามเดิม ไอคอนสร้างซ้ำได้ด้วย `node scripts/build-app-icons.mjs`

## ความจำ รูป/ไฟล์ และปฏิทิน

- รายการความจำและรายการปฏิทินทั้งหมดเป็นการ์ด 10 ช่องต่อแถวบนจอคอมพิวเตอร์ แบ่งหน้าละ 20 รายการ (2 แถว) พร้อมปุ่มก่อนหน้า/ถัดไปแยกกัน และเส้นคั่นก่อนรายการทั้งหมด; จอเล็กลดคอลัมน์เพื่อให้อ่านได้ กดการ์ดเพื่อแก้ไขได้เหมือนเดิม ความจำค้นหาจากข้อมูลทั้งหมดและแสดงผลล่าสุดสูงสุด 200 รายการ เมื่อเปลี่ยนคำค้นจะเริ่มหน้าแรก และเมื่อรายการลดลงจะกลับหน้าที่ยังมีข้อมูล
- เมนู **รูปและไฟล์** สร้างโฟลเดอร์เอง อัปโหลดไฟล์ไม่เกิน **3 MB ต่อไฟล์** แล้วแนบในความจำหรือปฏิทินได้สูงสุด **10 ไฟล์ต่อรายการ** รูป Shareable 1–4 ไฟล์ส่งเป็นภาพใน LINE; เมื่อรวมไฟล์แนบตั้งแต่ 5 ไฟล์ขึ้นไป ส่งเป็นการ์ดเลื่อนดูครบทุกไฟล์ โดยรูป Shareable มีภาพตัวอย่างและเอกสารมีปุ่มเปิด ลิงก์ Shareable มีอายุ 24 ชั่วโมง
- ไฟล์ใหม่พร้อมใช้ส่งให้กลุ่มโดยไม่ต้องเลือกสิทธิ์ แนบไฟล์ให้ความจำหรือปฏิทินก่อนส่ง ไม่ส่งไฟล์ทันทีที่อัปโหลด
- เก็บไฟล์ใน Supabase Storage bucket **pp-files** ซึ่งไม่เป็น public; ลบไฟล์/ลบ parent/ปิดกลุ่มจะปิดลิงก์กลุ่มเดิมด้วย แต่ไม่ลบสำเนาที่ดาวน์โหลดหรือส่งไปแล้ว
- เมนู **ปฏิทิน** เพิ่มวันเกิดหรือนัดหมาย เลือกทุกปี/เตือนวันนั้น/ก่อน 1 วัน ส่งส่วนตัวและ/หรือกลุ่มที่อนุมัติ แท็กเพื่อนที่ระบบรู้จักจากข้อความในกลุ่มได้ จำกัด 100 รายการ
- บันทึกรายการปฏิทินแล้วเปิดแจ้งเตือนอัตโนมัติทันที ไม่ต้องติ๊กสวิตช์เปิดอีก เลือกวันเตือนและผู้รับอย่างน้อยหนึ่งช่อง การเลือกวันเตือนใช้กับทุกปลายทางที่เลือก; รายการเก่าที่เคยปิดจะเปิดเมื่อบันทึกรายการนั้นอีกครั้ง
- แจ้งเตือนช่วง **08:00–09:00 น. เวลาไทย** ตาม Vercel Hobby Cron วันละครั้ง ไม่รองรับเวลารายรายการหรือส่งย้อนหลังวันถัดไป รายการ 29 ก.พ. เกิดเฉพาะปีอธิกสุรทิน
- หน้า Calendar แสดงโควตา LINE และผลส่งล่าสุด Push คิดจำนวนผู้รับ; Reply API ที่ใช้ตอบคำถามไม่หักโควตานี้

## เริ่มใช้งาน deployment นี้

ถ้าต้องการแท็กเจ้าของในคำตอบของความจำ ให้ติ๊ก **แท็กเจ้าของพร้อมคำตอบ** ในฟอร์มเพิ่มหรือแก้ไขความจำ ไม่ต้องพิมพ์ `@ชื่อ` ในช่องคำตอบ ระบบใช้ LINE user ID จากหน้าเจ้าของเพื่อสร้าง mention จริง โดยต้องเปิดสิทธิ์แท็กของกลุ่มและเจ้าของเป็นสมาชิกกลุ่ม เว้นห้านาทีระหว่างการแท็ก

**ถามความจำในแชตส่วนตัว LINE:** ทั้งเจ้าของและเพื่อนพิมพ์ถามบอทได้เลย ไม่ต้องใส่ `@pp` ถ้าไม่ตรงคำถามตัวอย่างจะใช้ Gemini ช่วยจับความหมายจากความจำ shareable ผู้ส่งที่ถูกพักจะไม่ได้รับคำตอบ บันทึก LINE user ID ในหน้าเจ้าของให้ตรงบัญชีเพื่อระบุเจ้าของและรักษาสิทธิ์ข้อมูลเก่า

ตาราง PP และค่าหลักสำหรับ LINE/Supabase ตั้งแล้ว ไม่ต้องรัน initial migration ซ้ำบนฐานข้อมูลนี้ ขั้นตอนด้านล่างใช้สำหรับติดตั้งใหม่ ส่วน Gemini ต้องตั้งค่าเพิ่มเติมตามหัวข้อถัดไป

1. ใน [Vercel Environment Variables](https://vercel.com/regener00-creators-projects/pp/settings/environment-variables) เติมค่าที่ขาดในตารางด้านล่าง เลือก Production และเก็บกุญแจเป็น Secret
2. ใน [Supabase API keys](https://supabase.com/dashboard/project/uyrwypfrvfhoryuvcujg/settings/api-keys) ใช้ secret key ฝั่งเซิร์ฟเวอร์ แนะนำสร้าง key ชื่อ PP เพื่อแยกการเพิกถอนคีย์ได้ อย่าเปลี่ยนคีย์ที่เว็บไซต์เดิมใช้อยู่
3. ใน [Supabase Authentication](https://supabase.com/dashboard/project/uyrwypfrvfhoryuvcujg/auth/users) ใช้บัญชีของคุณที่มีอีเมล/รหัสผ่าน หรือเพิ่มบัญชีสำหรับคุณผ่าน Dashboard คัดลอก UUID มาเป็น `ADMIN_USER_ID` ไม่ใช่ LINE user ID
4. Redeploy PP หลังเพิ่ม environment variables
5. เข้าสู่ระบบ `/admin` ตั้งชื่อและ LINE user ID ของเจ้าของ
6. สร้าง memory พร้อมชื่อและข้อมูลที่พร้อมให้บอทตอบในกลุ่ม คำถามตัวอย่างไม่จำเป็น ไม่ต้องเลือกสิทธิ์
7. ตั้งค่า LINE ตามหัวข้อถัดไป จากนั้นอนุมัติกลุ่มในแอดมิน

| ตัวแปร | จำเป็น | ที่มา/ความหมาย |
|---|---|---|
| `SUPABASE_URL` | ใช่ | URL ของ NOOSOL WEBSITE |
| `SUPABASE_PUBLISHABLE_KEY` | ใช่ | Publishable key หรือ legacy anon key ใช้กับ Auth |
| `SUPABASE_SECRET_KEY` | ใช่ | Secret key (`sb_secret_...`) หรือ legacy service_role key ใช้เฉพาะเซิร์ฟเวอร์ |
| `ADMIN_USER_ID` | ใช่ | UUID ของ Supabase Auth user ที่มีสิทธิ์แอดมินเพียงคนเดียว |
| `LINE_CHANNEL_SECRET` | ใช่ | Messaging API channel > Basic settings > Channel secret |
| `LINE_CHANNEL_ACCESS_TOKEN` | ใช่ | Messaging API channel > Channel access token |
| `OWNER_LINE_USER_ID` | ตัวเลือก | ค่าเริ่มต้นก่อนบันทึกเจ้าของในแอดมิน รูปแบบ `U` + hex 32 ตัว ค่าที่บันทึกในแอดมินมีลำดับเหนือกว่า |
| `ALLOW_TEXT_TRIGGER` | ตัวเลือก | `false` โดยปริยาย เปิด `true` เพื่อยอมรับการพิมพ์ `@น้องโจอา คำถาม` และชื่อเดิม `@pp คำถาม` โดยไม่เลือก mention ต้องเว้นวรรคหลังชื่อ |
| `CRON_SECRET` | ใช่ | สุ่มอย่างน้อย 32 ตัว ใช้ยืนยันงานตามเวลาและลงนามลิงก์ไฟล์ Shareable |

ทุกตัวเป็น server environment variable ห้ามตั้ง prefix `NEXT_PUBLIC_` ให้ secret key, channel secret, access token หรือ cron secret และไม่ต้องส่งกุญแจในแชต

## ตั้ง LINE Official Account

1. สร้าง/ใช้ Official Account ที่เปิด Messaging API แล้ว ตั้ง display name ว่า **PP**
2. เปิด **Allow bot to join group chats**
3. ใส่ Webhook URL ด้านบน เปิด **Use webhook** และ **Webhook redelivery** แล้วกด Verify
4. ปิดข้อความตอบกลับอัตโนมัติ/ข้อความทักทายของ Official Account หากไม่ต้องการให้ตอบซ้อนกับ PP
5. เชิญ PP เข้ากลุ่มที่เจ้าของอยู่ด้วย พิมพ์ `@` แล้วเลือกบัญชี **PP** จากรายการ LINE ไม่ใช่แค่พิมพ์ตัวหนังสือ
6. เรียก PP หนึ่งครั้ง กลุ่มจะถูกบันทึกเป็น **ยังไม่อนุมัติ** เข้า `/admin` > กลุ่มและสิทธิ์ แล้วเปิดกลุ่มนี้
7. ค่า owner LINE user ID ต้องอยู่ภายใต้ provider เดียวกับ Messaging API channel หาได้จาก LINE Developers Console ของเจ้าของ หรือจาก webhook ที่เชื่อถือได้ เป็นคนละค่ากับ Basic ID `@xxxx` และ display name

การ mention เจ้าของใช้ `textV2.substitution` จริง บอทตรวจสมาชิกกลุ่มก่อนแท็ก ถ้าตรวจไม่ได้จะไม่เดาว่าเจ้าของยังอยู่ในกลุ่ม ตาม [ข้อกำหนด LINE Text v2](https://developers.line.biz/en/reference/messaging-api/nojs/#text-message-v2)

- เมื่อเปิด Gemini: เข้าใจคำถามต่างสำนวนและชื่อ ปีโป้/ปป ตามคำแนะนำของโมเดล ถ้ากำกวมจะคืน unknown ไม่จำข้อความในกลุ่มอัตโนมัติ
- คืนเฉพาะคำตอบ shareable ที่ยังไม่หมดอายุ หาก private มีคำถามเดียวกัน private จะมีสิทธิ์ยับยั้งก่อน
- หากพบหลาย memory ที่ตอบคำถามเดียวกันและคำตอบ/ไฟล์/การแท็กต่างกัน จะขอให้เจ้าของตรวจ พร้อมเก็บคู่ความจำไว้ในคิว ถ้าเนื้อหาและพฤติกรรมเหมือนกันใช้ตอบได้
- คำตอบที่เจ้าของเพิ่มเองไม่ถูกปฏิเสธจากตัวกรองคำ ความจำเก่าที่มีสิทธิ์ private ยังถูก SQL ยับยั้ง และคำถามกำกวมหรือไม่มีคำตอบไม่ทำให้ AI แต่งข้อมูลเพิ่ม
- เรื่องชวน/นัด/ยืนยันที่ระบุเจ้าของและยังไม่มีคำตอบ จะพยายามแท็กเจ้าของ คำถามทั่วไปที่ไม่รู้จะตอบว่าไม่รู้
- ส่งได้สูงสุด 8 ครั้งต่อผู้ใช้ต่อกลุ่มใน 60 วินาที และแท็กเจ้าของไม่เกินหนึ่งครั้งต่อกลุ่มใน 5 นาที
- เจ้าของเป็นผู้ตัดสินใจว่าจะบันทึกอะไร คำตอบที่เพิ่มผ่านแอดมินพร้อมใช้ในกลุ่มที่เปิดใช้งาน ตัวกรองข้อมูลอ่อนไหวยังคงใช้กับการเรียนรู้บทสนทนาอัตโนมัติ
- คอลัมน์ visibility คงไว้เพื่อรองรับข้อมูลเก่า การแก้ชื่อ/เนื้อหาไม่เปลี่ยน private เก่าให้เป็น shareable และฟอร์มเก่าที่ขอสร้าง private จะให้รีเฟรชก่อน

ตัวอย่างในหน้าแรกเป็นข้อมูลสมมติสำหรับอธิบาย ไม่ได้บันทึกเป็นข้อมูลจริงของเจ้าของ

## โครงสร้าง

```text
src/app/api/line/webhook/   ตรวจลายเซ็นดิบ รับ webhook และจัดการ redelivery
src/lib/bot.ts             กลุ่มที่อนุมัติ → สิทธิ์เพื่อน → dedupe → policy → LINE
src/lib/owner-chat.ts      แชตส่วนตัว → ตรวจ sender/blocked → lease → direct RPC/AI → reply ส่วนตัว
src/lib/policy.ts          นโยบายตอบ/ปฏิเสธ/เรียกเจ้าของ
src/lib/line.ts            ตรวจ LINE event, mention และ HTTP client
src/lib/auth.ts            ตรวจบัญชีแอดมินกับ Supabase ทุกคำขอ
src/app/admin/             เว็บ CRUD memory, owner, permissions, friends, activity
supabase/migrations/      schema pp และฟังก์ชันฐานข้อมูล
tests/                    นโยบาย, LINE, webhook, admin, orchestration, PostgreSQL
```

ตารางใน schema `pp`: `owner`, `friends`, `memories`, `permissions`, `conversations`, `rate_limits`, `ai_usage`, `folders`, `files`, `calendar_events`, `reminder_deliveries`, `memory_issues`, `learning_messages`, `learning_runs`, `learning_suggestions`, `learning_unsent`

`conversations` เก็บ event/group/sender/message ID, source_type, สถานะ, decision และเวลาที่ใช้กันตอบซ้ำ แชตส่วนตัวมี group_id เป็น null **ไม่เก็บข้อความดิบ คำตอบ หรือเนื้อหา private** งาน Vercel Cron ล้างข้อมูลเกิน 30 วันทุกวัน 19:00 UTC (02:00 เวลาไทย)

## ความเป็นส่วนตัวและการใช้ฐานข้อมูลร่วม

ตารางทั้งหมดเปิด RLS และถอนสิทธิ์ `anon`/`authenticated` ทั้ง schema, tables, functions เข้าผ่านเซิร์ฟเวอร์หลังตรวจ Auth UUID หรือ webhook signature เท่านั้น ฟังก์ชันใช้ `SECURITY INVOKER` ไม่มีฟังก์ชันเปิดสิทธิ์สูงแก่ผู้ใช้ทั่วไป

Schema `pp` แยกชื่อตารางและ query จากแอปเดิม แต่ยังใช้ compute/storage/Auth/backup ร่วมกัน กุญแจเซิร์ฟเวอร์ Supabase มีสิทธิ์กว้างทั้งโปรเจกต์ จึงไม่ใช่การแยกขอบเขตเท่าฐานข้อมูลใหม่ หากต้องการแยกความเสียหายเมื่อกุญแจรั่ว ให้ย้าย PP ไป Supabase project ของตัวเองในภายหลัง

การใช้ Auth ร่วมไม่ทำให้ผู้ใช้ NOOSOL เป็นแอดมิน PP: ทุกหน้าและทุก Server Action ตรวจว่า user ID ตรงกับ `ADMIN_USER_ID` ก่อนอ่านเขียนข้อมูล ไม่ต้องเปลี่ยนนโยบายสมัครสมาชิกของ NOOSOL

สำหรับโปรเจกต์ใหม่ให้เพิ่ม `pp` ใน Exposed schemas โดยรักษารายชื่อเดิมไว้ และใช้ grants ที่ migration นี้กำหนด อย่าให้ anon/authenticated เข้าถึง PP ตามตัวอย่างทั่วไปในเอกสาร ดู [Supabase custom schemas](https://supabase.com/docs/guides/api/using-custom-schemas) และ [API access controls](https://supabase.com/docs/guides/api/securing-your-api)

## Gemini จับความหมาย (เปิดใช้งานแยกต่างหาก)

โมเดล `gemini-3.5-flash-lite` ผ่าน Google Cloud Agent Platform/Vertex AI โดยตรง เพื่อใช้บัญชีเครดิต Google ของเจ้าของ ไม่มี Vercel AI Gateway เป็นตัวกลาง ตั้ง `AI_ENABLED=true` เฉพาะหลังตรวจ billing และเรียกโมเดลจริงสำเร็จแล้ว

| ตัวแปร | การตั้งค่า |
|---|---|
| `AI_ENABLED` | `false` โดยปริยาย; เปิด `true` หลังตั้งกุญแจและทดสอบ |
| `AI_MONTHLY_LIMIT` | เริ่มที่ 1000; ลดได้ 1–1000; ค่าผิดจะปิด AI |
| `OWNER_ALIASES` | `ปีโป้,ปป` ตามชื่อที่เจ้าของระบุ |
| `GOOGLE_VERTEX_API_KEY` | Express-mode API key จำกัดบริการ Agent Platform เก็บเป็น Production Secret |
| `GOOGLE_VERTEX_PROJECT` + `GOOGLE_VERTEX_CREDENTIALS` | ทางเลือกใช้ project ID และ service account JSON แบบสิทธิ์น้อยที่สุด แทน API key |
| `GOOGLE_AUTH_MODE=vercel-oidc` | วิธีที่ใช้งานจริง: ตัวตนระยะสั้น Vercel Production ผ่าน Google Workload Identity โดยไม่ใช้กุญแจถาวร |
| `GOOGLE_WIF_AUDIENCE`, `GOOGLE_SERVICE_ACCOUNT_EMAIL` | ใช้ร่วมกับ project ID สำหรับ OIDC ดูค่าที่ตั้งและวิธีเพิกถอนใน [GOOGLE-IDENTITY.md](GOOGLE-IDENTITY.md) |

1. รัน migration `pp_semantic_matching` ก่อน deploy โค้ดใหม่ (ทำแล้วสำหรับฐานข้อมูลนี้)
2. เปิดบริการ Google ที่จำเป็นและตรวจเครดิต/สถานะ billing ถ้ามีขั้นตอนอัปเกรดหรือเติมเงิน เจ้าของต้องเลือกก่อน
3. สร้าง credential เฉพาะ PP จำกัดบริการ/สิทธิ์ เก็บที่ Vercel Production ห้ามส่งในแชตหรือใช้ `NEXT_PUBLIC_`
4. ทดสอบ Gemini ด้วยข้อมูลสมมติ แล้วเปิด `AI_ENABLED=true` และ redeploy
5. เพิ่ม memory จริงของเจ้าของ เช่น คำถาม “ปีโป้ชอบรับประทานอะไร” พร้อมคำตอบที่เจ้าของยืนยัน แล้วลอง “@pp ปปชอบกินอะไร”

**ขอบเขตข้อมูล:** SQL คืน ID ชื่อ เนื้อหา และตัวอย่างคำถาม Shareable ที่ยังไม่หมดอายุให้ตัวเลือก AI รวมคำถามที่ผู้ใช้พิมพ์; private และ LINE user IDs ไม่ส่งให้โมเดล โมเดลคืนได้เฉพาะ ID ที่อยู่ในชุด หรือ unknown/refuse/conflict จากนั้น SQL ตรวจสิทธิ์, visibility, expiry และ fingerprint ของแถวซ้ำก่อนคืนคำตอบ แชตส่วนตัวใช้ `pp_direct_answer` และ `pp_direct_ai_candidates` / `pp_direct_ai_answer` ตรวจ sender, blocked และ lease ก่อนและหลัง AI เฉพาะเจ้าของปัจจุบันใช้ exact `pp_owner_answer` สำหรับ private เก่าได้ การตรวจความจำในแอดมินอ่าน manual shareable รวมก้อนหมดอายุเพื่อช่วยจัดระเบียบ ไม่มีการเก็บ prompt/response ดิบหรือ provider exception

**ข้อจำกัด:** semantic matching เป็นการคาดคะเนและอาจจับคู่ผิด ไม่รับประกันเข้าใจทุกสำนวน ห้ามใช้เป็นแหล่งข้อมูลอ่อนไหว ถึง model เลือก ID ผิดก็เข้าถึงได้เฉพาะคำตอบ Shareable ที่เจ้าของอนุมัติ คำถามตัวอย่างที่ซ้ำกับ private ถูกยับยั้งใน SQL แต่ไม่ตรวจความหมายของ private ด้วย AI เพราะไม่ส่ง private ออกไป หากต้องการบังคับตรงคำถามเท่านั้น ให้ปิด `AI_ENABLED`

**โควตา:** จองสิทธิ์เรียกใน Postgres ก่อนส่งคำขอ พร้อมกันหลาย instance ก็ไม่เกิน 1000 ครั้ง/เดือน รวมทุกกลุ่ม แชตส่วนตัว และการตรวจความจำ เริ่มใหม่วันที่ 1 เวลา Asia/Bangkok ไม่ทบยอด คำขอล้มเหลว/หมดเวลายังนับหนึ่งครั้ง; จำกัดเพิ่ม 6 ครั้ง/นาที, 500 ตัวอักษรต่อคำถาม ไม่มีเพดาน 40 ก้อนเดิม แต่ prompt+system รวมต้องไม่เกิน 128,000 bytes การจับคู่ output ไม่เกิน 512 tokens/timeout 12 วินาที; การตรวจความจำ output ไม่เกิน 4000 tokens/timeout 18 วินาที ทุกเส้นทาง retry 0 ไม่มีเครื่องมือค้นเว็บหรือ grounding

เมื่อไม่มี memory, โควตาเต็ม, ชุดข้อมูลใหญ่เกินไป หรือ Google ล้มเหลว ระบบกลับไป unknown/เรียกเจ้าของตามนโยบายเดิม คำถามตรงตัวอย่างยังตอบได้โดยไม่เรียก AI ตัวนับควบคุมเฉพาะโค้ด PP ไม่จำกัดการเรียกจากที่อื่น ไม่ตรวจยอดเครดิต Google แบบทันที และไม่รับประกันว่าจะไม่มีค่าใช้จ่ายหากเครดิตหมดหรือหมดอายุ

ราคาอ้างอิง 29 กันยายน 2026: Gemini 3.5 Flash-Lite global input $0.30/output $2.50 ต่อ 1 ล้าน tokens (รวม reasoning ใน output) ค่าใช้จริงขึ้นกับความยาวชื่อ เนื้อหาทุกก้อน คำถาม และผลตรวจ จึงมากกว่าแบบส่งเฉพาะตัวอย่างคำถามเดิม ดู [ราคา Google](https://cloud.google.com/gemini-enterprise-agent-platform/generative-ai/pricing) และ [รายละเอียดโมเดล](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/gemini/3-5-flash-lite)

ตรวจสถานะและยอดเดือนนี้ที่ `/admin#ai` ปิดฉุกเฉินด้วย `AI_ENABLED=false` แล้ว redeploy หากต้องการถอดโค้ด semantic ให้ rollback deployment เดิมได้ ตาราง/ฟังก์ชันใหม่เป็นส่วนเพิ่ม ไม่เปลี่ยนข้อมูลแอป NOOSOL

## Deployment และการดูแล

```sh
npx vercel@60.1.3 login
npx vercel@60.1.3 deploy --prod --project pp --scope regener00-creators-projects --yes
```

Vercel Function ใช้ Node และตั้ง region `sin1` ใกล้ Supabase Singapore, webhook มีเวลาไม่เกิน 60 วินาทีและทุก network call มี timeout งานถูก await ก่อนตอบ HTTP เพื่อให้ LINE redelivery รับช่วงเมื่อเกิดข้อผิดพลาด ไม่มีงานเบื้องหลังที่อาจถูกตัดหลังตอบ 200

- `webhookEventId` ใช้กันซ้ำในฐานข้อมูล Lease 90 วินาทีกันคำขอพร้อมกันและอนุญาตให้รับงานที่หลุดกลับมาทำใหม่ ลองสูงสุด 3 ครั้ง
- LINE reply token ใช้ได้ครั้งเดียว หากหมดอายุหรือส่งซ้ำ API ตอบ 400 จะบันทึก `expired` ไม่ส่ง push ตามหลัง
- ถ้า LINE ส่งสำเร็จแต่การบันทึกสถานะล้มเหลว การ retry อาจจบเป็น `expired` แม้ข้อความส่งไปแล้ว ตรวจ LINE ร่วมกับสถานะ
- แถว `failed` คือส่งไม่สำเร็จหรือสิทธิ์/การเชื่อมต่อผิด ให้ตรวจค่า environment และ LINE Console; เปิด redelivery มิฉะนั้น 503 จะไม่ถูกส่งใหม่
- ถ้า LINE redelivery มาช้ากว่าอายุ reply token อาจไม่ได้คำตอบ นี่เป็นระบบสำหรับกลุ่มขนาดเล็ก ไม่ใช่ระบบคิวที่รับประกันการส่งทุกข้อความ
- เปลี่ยน visibility/ลบ memory มีผลกับคำขอใหม่ทันที ไม่มี cache คำตอบ แต่ลบข้อความที่ส่งเข้า LINE ไปแล้วไม่ได้
- Server logs แสดงเฉพาะรหัสความผิดพลาดและจำนวน ไม่ dump webhook, secret หรือ memory
- ขณะนำระบบขึ้นจริงให้ลอง shareable, private, unknown invite, unknown general, กลุ่มที่ไม่ได้อนุมัติ และการถอด owner ออกจากกลุ่ม ด้วยข้อมูลทดสอบที่คุณอนุญาต

อ้างอิงการตรวจลายเซ็นและการรับ webhook: [LINE webhooks](https://developers.line.biz/en/docs/messaging-api/receiving-messages/) ส่วน Server Actions ตรวจสิทธิ์ทุกครั้งตาม [Next.js data security](https://nextjs.org/docs/app/guides/data-security)
